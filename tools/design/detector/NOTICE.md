# NOTICE — kit design detector (commons)

`tools/design/detector/` is the kit's own Python reimplementation (built on the studio station, promoted to the
commons by RETURNS/reconcile-01.md) of the design-detector rules of
**Impeccable** by Paul Bakaus — https://github.com/pbakaus/impeccable — at commit
`5bf0a069dc857e1b5f4b090e004d9d5b231416ca`, licensed under the Apache License 2.0
(full text: `tests/upstream/LICENSE`, also held at `repertoire/pbakaus~impeccable/LICENSE` on station studio).

What comes from upstream, and how it is used:

| what | where here | form |
|---|---|---|
| rule ids, names, descriptions, categories, severities, scopes (59 rules) | `registry.json` | copied as data, unmodified text |
| copy-rule word lists (marketing buzzwords, aphorism shapes, "theater" head words), font lists, thresholds | `rules_*.py`, `regex_engine.py` | values restated in our code |
| detection logic | every `*.py` here | re-implemented in Python from reading the Rust source at the pin; no upstream code is copied or run |
| test fixtures (`tests/fixtures/antipatterns/`, 209 entries) | `tests/upstream/fixtures/` | copied verbatim, unmodified |
| expected findings per fixture (from `tests/oracle/golden/detect-fixture-json-*.json`) | `tests/upstream/expected.json` | rule-id counts extracted |

Changes from upstream: see `PORT_MAP.md` § "Deliberate differences". The upstream engine's telemetry and network
calls are not reproduced: this detector makes no network requests and records nothing.

Impeccable's own NOTICE (carried): it includes `skill/reference/ios.md` and `skill/reference/android.md` distilled
from ehmo's `platform-design-skills` (MIT). The detector does not use those files.

The repo-level `NOTICE.md` is generated by the commons tool `tools/upstream/notice.py`, which has no input for
derived works yet; RETURNS/studio-v2.md hands that section to its owner.
